### Python Engine Integration Details

**Process Spawning Pattern:**
```typescript
import { spawn } from 'child_process';
import { execSync } from 'child_process';

// Python discovery
function findPython(): string {
  const candidates = process.platform === 'win32'
    ? ['python', 'py', 'python3']
    : ['python3', 'python'];

  for (const cmd of candidates) {
    try {
      execSync(`${cmd} --version`, { stdio: 'ignore' });
      return cmd;
    } catch {
      // Not available, try next
    }
  }
  throw new Error('Python not found. Install Python 3.10+ to use transformation features.');
}

// Process with timeout and cleanup
function spawnWithTimeout(
  command: string,
  args: string[],
  timeout: number = 30000
): Promise<{ stdout: string; stderr: string; exitCode: number }> {
  return new Promise((resolve, reject) => {
    const proc = spawn(command, args);
    let stdout = '';
    let stderr = '';
    const timer = setTimeout(() => {
      proc.kill('SIGKILL');
      reject(new Error(`Process timed out after ${timeout}ms`));
    }, timeout);

    proc.stdout.on('data', (d) => { stdout += d.toString(); });
    proc.stderr.on('data', (d) => { stderr += d.toString(); });

    proc.on('close', (code) => {
      clearTimeout(timer);
      resolve({ stdout, stderr, exitCode: code ?? 1 });
    });

    proc.on('error', (err) => {
      clearTimeout(timer);
      reject(err);
    });
  });
}
```

### Testing Standards

**Integration Tests** (Jest, runs against real Python engine):
- Use `describe('Python Engine Integration', () => { ... })` grouping
- Skip tests gracefully if Python is not available: `process.env.CI ? fail('Python required') : test.skip(...)`
- Test real I/O: file reads, process spawns, API calls
- Assert on both success AND error paths
- Measure performance (duration assertions)

**E2E Tests** (Playwright, runs against live dev server):
- Use `test.describe('Full Stack', () => { ... })` grouping
- Start Next.js dev server before tests
- Test full user flows, not just API endpoints
- Clean up test files after each test
- Assert on UI state where applicable

**Python Tests** (pytest, runs against engine):
- Place in `tests/python/` directory
- Use `pytest.fixture` for test setup
- Test engine pipeline: parse â†’ validate â†’ generate
- Test error handling for malformed input
- Run via `npm run test:python` â†’ `pytest tests/python/`

### Technical Constraints

- **Python version**: 3.10+ required
- **Transform timeout**: 30 seconds max per file
- **Concurrent transforms**: Max 4 parallel Python processes
- **File size limit**: 1MB per source file
- **Encoding**: UTF-8 only (with Latin-1 fallback + warning)
- **Round-trip fidelity**: XML structure must be preserved (whitespace differences OK)
- **Performance**: < 5 seconds per transform, < 30 seconds for batch of 10

### Security Considerations

- **Directory traversal prevention**: Validate all file paths stay within project root
- **Input sanitization**: Strip BOM, normalize line endings, reject binary input
- **Process isolation**: Kill Python processes on timeout, prevent zombie processes
- **Resource limits**: Max 4 concurrent Python processes, max 1MB input size
- **Error message sanitization**: Don't expose internal file paths or stack traces to users
