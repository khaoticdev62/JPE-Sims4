# Story 1.5: Save Project & Real-Time Validation

**Status**: Done - Ready for QA

---

## Story

**As a** user editing mod files,
**I want my changes saved reliably to disk with automatic backups, and see validation errors as I type,
**so that** I don't lose work and can catch mistakes immediately.

---

## Acceptance Criteria

1. **Save Compiles JPEâ†’XML First** â€” When saving a JPE file, it compiles to XML before writing to disk
2. **Backup on Save** â€” Previous version of file backed up before overwrite
3. **Dirty State Cleared** â€” Tab `*` indicator removed after successful save
4. **Server-Side Save API** â€” `/api/files/write` route handles file saves (works without Electron)
5. **Real-Time Validation** â€” Errors shown in editor as user types (500ms debounce)
6. **Live Preview Updates** â€” Valid JPE edits update XML preview in real-time
7. **Multi-File Save** â€” Ctrl+Shift+S saves all dirty files
8. **Tests** â€” Unit tests for save pipeline, validation hook, server save route

## Tasks / Subtasks

### **Task 1**: Server-Side Save API Route

`FileService.writeFile` uses Electron IPC. The web app needs a server-side route.

- [ ] **Subtask 1.1**: Create `/api/files/save` route
  - Accept `{ path, content, createBackup: boolean }`
  - Use `FileServiceEnhanced.writeFile()` for atomic writes with backup
  - Validate path stays within project root
  - Return `{ success, size, backupPath }`

- [ ] **Subtask 1.2**: Create browser-compatible file save utility
  - `BrowserFileService.saveFile(path, content)` calls `/api/files/save`
  - Falls back to Electron IPC when in Electron environment
  - Returns same interface as Electron-based FileService

---

### **Task 2**: Save Should Compile JPEâ†’XML

When user edits JPE and saves, the disk should get valid XML.

- [ ] **Subtask 2.1**: Update `saveFile` to detect JPE files
  - If file type is `jpe`: compile JPEâ†’XML via `CompilerService.compileWithPython()` first
  - Save compiled XML to the original XML file path (stored in `originalXml`)
  - If file type is `xml` or other: save content as-is

- [ ] **Subtask 2.2**: Handle compile failure during save
  - If JPEâ†’XML compile fails: show error dialog with validation errors
  - Do NOT save invalid content
  - Offer: "Save as JPE anyway" or "Fix errors first"

- [ ] **Subtask 2.3**: Save success feedback
  - Toast: "Saved: filename.xml (1.2KB)"
  - Clear dirty flag on tab
  - Update file timestamp in project store

### **Task 3**: Backup on Save

- [ ] **Subtask 3.1**: Enable backup in save pipeline

- [ ] **Subtask 3.2**: Backup management UI
  - Show backup location in save success message
  - Settings option: "Enable auto-backup" (default: on)
