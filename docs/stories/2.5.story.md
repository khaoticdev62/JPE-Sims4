# Story 2.5: High-Fidelity Round-Trip Validation

## Story

**As a** Modder working with existing Sims 4 mods,
**I want** a validation system that ensures zero data loss during JPE↔XML conversion,
**so that** I can confidently decompile, edit, and recompile existing mods without breaking them.

---

## Acceptance Criteria

1. **Round-Trip Verification** — XML → JPE → XML produces functionally identical output
2. **Deviation Detection** — Any data or logic differences between source and result trigger critical errors
3. **Detailed Diff Report** — Differences shown side-by-side with exact element paths affected
4. **Tolerance Configuration** — User can configure strictness (strict=byte-identical, lenient=functionally-equivalent)
5. **Tests** — Round-trip tests with 5+ real Sims 4 XML tuning files; 100% pass rate

---

## Tasks / Subtasks

### **Task 1**: Round-Trip Validator Engine

Create the core validation engine that compares source and round-tripped output.

- [ ] **Subtask 1.1**: Create `RoundTripValidator` class
  - Accept original XML and round-tripped XML
  - Perform structural comparison (element tree, attributes, text content)
  - Ignore whitespace/formatting differences (normalized comparison)
  - Return list of differences with severity levels

- [ ] **Subtask 1.2**: Comparison modes
  - **Strict**: Byte-identical after normalization
  - **Functional**: Same logical structure and data (attribute order doesn't matter)
  - Report mode used in validation result

- [ ] **Subtask 1.3**: Diff generation
  - For each difference: element path, expected vs actual, severity
  - Aggregate statistics (N differences, X critical, Y warnings)

---

### **Task 2**: Integration with Decompilation Pipeline

Wire validator into the XML→JPE→XML round-trip flow.

- [ ] **Subtask 2.1**: Auto-validate on round-trip
  - When user decompiles XML→JPE then recompiles JPE→XML
  - Automatically run round-trip validator
  - Block save if critical differences detected (with override option)

- [ ] **Subtask 2.2**: Visual diff viewer
  - Side-by-side XML comparison panel
  - Highlight differences in red/green
  - Navigate between diffs with keyboard shortcuts

---

### **Task 3**: Test Suite with Real Mods

- [ ] **Subtask 3.1**: Gather test fixtures
  - Collect 5+ real Sims 4 XML tuning files covering different types
  - Include simple tuning, complex interactions, conditional tests
  - Verify each file is valid Sims 4 XML

- [ ] **Subtask 3.2**: Round-trip integration tests
  - For each test file: XML → JPE → XML → compare
  - All must pass functional equivalence
  - Document any acceptable differences (e.g., attribute ordering)

- [ ] **Subtask 3.3**: Edge case tests
  - Empty XML files
  - XML with CDATA sections
  - XML with special characters in attributes

### **Task 4**: Error Handling & User Feedback

- [ ] **Subtask 4.1**: Critical error blocking

  - "Save Anyway" (with confirmation) vs "Cancel and Fix"
  - Log all round-trip failures for debugging

- [ ] **Subtask 4.2**: Success confirmation
  - Green checkmark + "Round-trip verified: 100% fidelity" toast
  - Update file metadata with validation timestamp

## Dev Notes

### Round-Trip Tolerance

Some differences are acceptable:
- Attribute ordering within same element (XML parsers don't guarantee order)
- Whitespace in text nodes (normalized during parsing)
- Entity encoding (`&amp;` vs `&` in attributes)

Critical differences that must fail validation:
- Missing or extra elements
- Different attribute values
- Different text content
- Changed element hierarchy
