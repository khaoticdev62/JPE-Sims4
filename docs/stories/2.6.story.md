# Story 2.6: Nested Condition Prototype (Spike)

## Story

**As a** Modder creating complex game logic,
**I want** the translator to handle deeply nested ONLY_IF/WHEN/DO blocks,
**so that** I can build sophisticated conditional logic without manually writing XML test lists.

---

## Acceptance Criteria

1. **Nested Block Parsing** — JPE with 2+ levels of nested conditions parsed correctly ✅
2. **XML Test List Generation** — Nested blocks flattened/nested into proper Sims 4 `<L>` and `<V>` elements ✅
3. **ID Resolution for Anonymous Tests** — Nested unnamed test blocks get unique, collision-free IDs ✅
4. **Scope Isolation** — Properties in parent/child scopes don't collide ✅
5. **Prototype Output** — Spike produces working translation for a sample nested JPE file ✅
6. **Documentation** — Spike findings documented with recommended approach for full implementation ✅

### Spike Findings

**✅ What Worked Well**:
- Recursive descent parsing handles deep nesting elegantly
- Scope isolation prevents property name collisions
- Hash-based ID generation ensures uniqueness
- XML test list generation produces valid Sims 4 structure

**⚠️ Challenges Identified**:
- Condition parsing needs integration with JPETokenizer for complex conditions
- Action mapping needs extensible registry (currently basic map)
- Flattening vs nesting strategy decision needed for performance

### Example: 3-Level Nesting

**Input JPE**:
```jpe
WHEN sim_has_trait("creative") DO
  interaction_apply_buff("inspiration")
  ONLY_IF sim_has_buff("focused")
    interaction_set_value("creativity", 150)
    ONLY_IF sim_relationship_level("mentor") > 75
      interaction_unlock_option("masterclass")
    END
  END
END
```

**Output XML**:
```xml
<?xml version="1.0" encoding="UTF-8"?>
<C>
  <L>
    <V t="trait" n="0x..." />
    <L>
      <V t="buff" n="0x..." />
      <L>
        <V t="relationship" n="0x..." />
      </L>
    </L>
  </L>
</C>
```
