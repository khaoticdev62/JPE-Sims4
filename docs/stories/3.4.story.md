# Story 3.4: Semantic Intelligence & Reference Checking

## Story

**As a** Modder,
**I want** the editor to warn me when my JPE references undefined interactions, buffs, or traits,
**so that** my game doesn't crash from missing dependencies at runtime.

---

## Acceptance Criteria

1. **Reference Resolution** — Every referenced ID or name validated against project definitions or known Sims 4 API sets
2. **Undefined Reference Errors** — Missing components reported with "Undefined Reference" semantic errors
3. **Known Set Validation** — Validate against built-in Sims 4 element registry (traits, buffs, interactions)
4. **Cross-File Checking** — References validated across all files in the project
5. **Tests** — Unit tests for reference checker; integration test with multi-file mod projects

---

## Tasks / Subtasks

### **Task 1**: Symbol Table Builder

Build a registry of all defined symbols in the project.

- [ ] **Subtask 1.1**: Create `SymbolTable` class
  - Track definitions: interactions, buffs, traits, conditions
  - Each symbol: name, ID, file path, line number, type
  - Support add/remove/update as files change

- [ ] **Subtask 1.2**: Project-wide indexing
  - Scan all open files for definitions
  - Extract symbol definitions from JPE (WHEN sim_has_trait("X") → defines reference to trait "X")
  - Re-index on file change (incremental)

---

### **Task 2**: Reference Checker

Validate all references against the symbol table.

- [ ] **Subtask 2.1**: Create `ReferenceChecker` class
  - Parse JPE for references (trait names, buff IDs, interaction names)
  - Check each reference against SymbolTable
  - Check against built-in Sims 4 registry for known elements
  - Report undefined references with position info

- [ ] **Subtask 2.2**: Built-in Sims 4 registry
  - Load known Sims 4 element database (traits, buffs, interactions)
  - Support version-specific registries (game updates change IDs)
  - Allow user to update registry from game files

- [ ] **Subtask 2.3**: Cross-file resolution
  - References in file A validated against definitions in file B
  - Handle file-level vs project-level scope
  - External references (to installed mods) flagged as "external"

---

### **Task 3**: Integration with Validation Pipeline

Wire semantic checks into the debounced validation flow.

- [ ] **Subtask 3.1**: Run reference checker during semantic validation phase
  - After syntax validation passes, run reference checking
  - Report results as warnings (not errors, since reference might be in game)

- [ ] **Subtask 3.2**: Quick-fix suggestions
  - For undefined references: suggest similar names from registry
  - "Did you mean: <similar_trait>?" suggestions
  - Link to add definition template

---

### **Task 4**: Tests

- [ ] **Subtask 4.1**: Unit tests for SymbolTable
  - Add/remove symbols correctly
  - Lookup by name and ID
  - Incremental update on file change

- [ ] **Subtask 4.2**: Unit tests for ReferenceChecker
  - Defined reference → no error
  - Undefined reference → "Undefined Reference" error
  - Built-in reference → validated against registry
  - Similar name suggestions for typos

- [ ] **Subtask 4.3**: Integration test
  - Multi-file project with cross-references
  - Add reference to undefined trait → warning appears
  - Add definition → warning resolves

## Dev Notes

### Sims 4 Element Registry

Need to maintain a registry of known Sims 4 elements:
- Traits: gene_* IDs, names
- Buffs: buff_* IDs, names
- Interactions: interaction_* IDs, names
- Objects: object_* IDs

This can be extracted from Sims 4 game files or sourced from community databases.

### Reference Types

JPE references include:
- `sim_has_trait("trait_name")` → trait reference
- `sim_has_buff("buff_name")` → buff reference
- `interaction_apply_buff("buff_name")` → buff reference
- `interaction_unlock_option("interaction_name")` → interaction reference
