# Story 4.1: XML-to-JPE Reverse Compiler (Decompiler)

## Story

**As a** Modder working with existing Sims 4 mods,
**I want** to open XML tuning files and see them decompiled into readable JPE,
**so that** I can understand and edit existing mods without reverse-engineering XML manually.

---

## Acceptance Criteria

1. **XML → JPE Decompilation** — Valid Sims 4 XML tuning files translated to human-readable JPE format
2. **Logic Block Reconstruction** — All `<L>` and `<V>` test lists reconstructed as WHEN/DO/ONLY_IF blocks
3. **Full Editability** — Decompiled JPE immediately editable with full syntax highlighting
4. **Round-Trip Fidelity** — Decompiled JPE recompiles to functionally identical XML
5. **Tests** — Unit tests for decompiler; integration tests with 5+ real Sims 4 XML tuning files

---

## Tasks / Subtasks

### **Task 1**: XML-to-JPE Decompiler Engine

Create the core decompilation service.

- [ ] **Subtask 1.1**: Create `XMLToJPEDecompiler` class
  - Parse XML DOM structure
  - Identify tuning element types (interaction, buff, trait, etc.)
  - Extract attributes and map to JPE properties

- [ ] **Subtask 1.2**: Test list decompilation
  - Parse `<L>` (logical list) elements → WHEN/ONLY_IF blocks
  - Parse `<V>` (test value) elements → condition expressions
  - Handle AND/OR logic in test lists
  - Reconstruct nested block structure

- [ ] **Subtask 1.3**: JPE output formatting
  - Generate readable JPE text with proper indentation
  - Use descriptive names where possible (instead of raw IDs)
  - Include comments for complex logic

Wire decompiler into the file loading flow.

- [ ] **Subtask 2.1**: Auto-detect XML tuning files

  - If yes: decompile to JPE for display

- [ ] **Subtask 2.2**: Editor mode switching
  - Show decompiled JPE in editor with JPE syntax highlighting

## Dev Notes

### Decompilation Strategy

XML → JPE mapping:
- `<C n="interaction">` → `INTERACTION "interaction"`
- `<L>` with tests → `WHEN <test_conditions> DO`
- `<V t="trait" n="0x...">` → `sim_has_trait("trait_name")`
- `<V t="buff">` → `sim_has_buff("buff_name")`

ID-to-name resolution: use symbol table and Sims 4 registry to convert raw IDs to readable names.
