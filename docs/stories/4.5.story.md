# Story 4.5: High-Performance Parallel Compilation

## Story

**As a** Modder managing large mod overhaul projects,
**I want** the compiler to process hundreds of files simultaneously using multiple cores,
**so that** full project builds complete in seconds, not minutes.

---

## Acceptance Criteria

1. **Multi-Core Compilation** — 100+ JPE/XML files compiled in parallel
2. **<5 Second Target** — 100 typical files compiled in under 5 seconds
3. **Progress Reporting** — Real-time progress bar with file count and ETA
4. **Error Aggregation** — Errors from all files collected and displayed in diagnostics
5. **Tests** — Unit tests for parallel executor; benchmark test for 100-file compilation

---

## Tasks / Subtasks

### **Task 1**: Parallel Compilation Engine

Create the multi-core compilation orchestrator.

- [ ] **Subtask 1.1**: Create `ParallelCompiler` class
  - Accept list of files to compile
  - Distribute work across worker threads (default: CPU count - 1)
  - Collect results and aggregate errors

- [ ] **Subtask 1.2**: Worker pool management
  - Pre-warm worker threads on app start
  - Reuse workers across compilation runs
  - Handle worker crashes gracefully (restart and retry)

- [ ] **Subtask 1.3**: Resource throttling
  - Limit concurrent workers to prevent memory exhaustion
  - Configurable max workers (default: logical cores - 1)
  - Backpressure when queue is full

---

### **Task 2**: Progress Reporting

- [ ] **Subtask 2.1**: Real-time progress tracking
  - Track completed/total files
  - Calculate ETA based on average compile time
  - Show current file being processed

- [ ] **Subtask 2.2**: Progress UI
  - Progress bar in status bar or modal
  - Cancel button for long-running builds
  - Summary toast on completion (success/failure counts)

---

### **Task 3**: Error Aggregation

- [ ] **Subtask 3.1**: Collect errors from all workers
  - Each worker returns compile result (success or error list)
  - Merge all errors into single diagnostic report
  - Sort errors by file path and line number

- [ ] **Subtask 3.2**: Partial build results
  - Even with errors, output successfully compiled files
  - Mark failed files in build report
  - Allow "Retry Failed" for transient errors

---

### **Task 4**: Tests

- [ ] **Subtask 4.1**: Unit tests for ParallelCompiler
  - Distribute files across workers correctly
  - Handle worker crash → retry on different worker
  - Aggregate results accurately

- [ ] **Subtask 4.2**: Benchmark test
  - Generate 100 sample JPE files
  - Compile in parallel → measure time
  - Verify <5 second target met

- [ ] **Subtask 4.3**: Stress test
  - 500 files → verify no memory leaks
  - 1000 files → verify stable operation

## Dev Notes

### Worker Architecture

```
Main Thread                    Worker Pool
┌──────────────┐              ┌─────────┐
│ File Queue   │──dispatch──→ │ Worker 1 │
│              │──dispatch──→ │ Worker 2 │
│ Progress     │←─result───── │ Worker 3 │
│ Aggregator   │←─result───── │ ...     │
└──────────────┘              └─────────┘
```

Each worker:
1. Receives file path and content
2. Runs appropriate compiler (JPE→XML or XML→JPE)
3. Returns result (output or errors)
