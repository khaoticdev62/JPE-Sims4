# Story 5.3: Keyboard-Only Navigation & WCAG Compliance

## Story

**As a** Modder who prefers keyboard navigation or has accessibility needs,
**I want** to navigate the entire IDE using only the keyboard,
**so that** I can work efficiently without a mouse.

---

## Acceptance Criteria

1. **Tab/Arrow Navigation** — Focus moves logically between all interactive elements
2. **High-Visibility Focus Indicator** — Clear focus ring on active element (Spectral teal glow)
3. **Discoverable Shortcuts** — All primary actions have keyboard shortcuts shown in UI
4. **Logical Focus Order** — Tab order follows visual layout (left-to-right, top-to-bottom)
5. **No Keyboard Traps** — Focus can always exit any component
6. **Tests** — Accessibility audit with axe-core; keyboard navigation E2E tests

---

## Tasks / Subtasks

### **Task 1**: Keyboard Navigation System

Implement comprehensive keyboard navigation.

- [ ] **Subtask 1.1**: Define keyboard shortcuts
  - `Ctrl+N`: New file
  - `Ctrl+O`: Open file
  - `Ctrl+S`: Save
  - `Ctrl+W`: Close tab
  - `Ctrl+Tab`: Next tab
  - `Ctrl+Shift+Tab`: Previous tab
  - `Ctrl+B`: Build/Compile
  - `Ctrl+P`: Quick file open (command palette)
  - `F1`: Show all shortcuts
  - `Escape`: Close panel/modal

- [ ] **Subtask 1.2**: Focus management
  - Track focus state across the app
  - Move focus on panel open/close
  - Return focus to trigger element on modal close
  - Prevent focus loss on DOM updates

### **Task 2**: Visual Focus Indicators

Style focus for all interactive elements.

- [ ] **Subtask 2.1**: Global focus styles
  - Spectral teal outline (2px solid + 2px offset) for focused elements
  - High contrast against any theme
  - No outline for mouse users (detect pointer type)

- [ ] **Subtask 2.2**: Component-specific focus
  - Tree items: focus ring around entire row
  - Tabs: focus ring around tab button
  - Buttons: raised glow effect
  - Editor: visible cursor position

---

### **Task 3**: ARIA Attributes & Roles

Add accessibility markup to all components.

- [ ] **Subtask 3.1**: ARIA roles
  - `role="tree"` for file explorer
  - `role="tablist"` / `role="tab"` for editor tabs
  - `role="dialog"` for modals
  - `role="status"` for status bar
  - `aria-label` for icon-only buttons

- [ ] **Subtask 3.2**: State attributes
  - `aria-expanded` for collapsible sections
  - `aria-selected` for active tabs
  - `aria-checked` for toggles
  - `aria-disabled` for disabled controls

## Dev Notes

### Focus Management Strategy

Use a focus trap library (e.g., `focus-trap-react`) for modals and panels. For general navigation, rely on natural DOM focus order with `tabindex` adjustments where needed.

### Pointer Type Detection

```css
/* Only show focus outline for keyboard navigation */
:focus-visible {
  outline: 2px solid #2EC4B6;
  outline-offset: 2px;
}

:focus:not(:focus-visible) {
  outline: none;
}
```
