# Story 5.4: Screen Reader Support & ARIA Labeling

## Story

**As a** Visually Impaired Modder using a screen reader,
**I want** the application to announce UI state and code content accessibly,
**so that** I can understand the interface and work with my mods independently.

---

## Acceptance Criteria

1. **Descriptive ARIA Labels** — All buttons and inputs have meaningful labels
2. **Tree View Announcements** — File tree reports expanded/collapsed states correctly
3. **Diagnostic Announcements** — New errors announced when they occur
4. **Editor Accessibility** — Code content readable by screen readers
5. **Tests** — Screen reader compatibility tests; ARIA label audit

---

## Tasks / Subtasks

### **Task 1**: Comprehensive ARIA Labeling

Audit and fix all ARIA labels across the application.

- [ ] **Subtask 1.1**: Button and icon labels
  - Every icon button has `aria-label` describing action
  - No "click here" or vague labels
  - Labels include context where needed (e.g., "Close tab 'myfile.jpe'")

- [ ] **Subtask 1.2**: Form input labels
  - Every input associated with a label element
  - `aria-describedby` for help text
  - Error messages linked via `aria-errormessage`

---

### **Task 2**: Tree View Accessibility

Make the file tree fully accessible.

- [ ] **Subtask 2.1**: Tree ARIA structure
  - `role="tree"` on container
  - `role="treeitem"` on each item
  - `aria-expanded` reflects state
  - `aria-level` for nesting depth

- [ ] **Subtask 2.2**: Announcements
  - "Directory expanded" when opening folder
  - "Directory collapsed" when closing
  - "File selected: filename.jpe" on focus

---

### **Task 3**: Live Region Announcements

Use ARIA live regions for dynamic updates.

- [ ] **Subtask 3.1**: Diagnostic announcements
  - `aria-live="polite"` region for new errors
  - Announce "X errors found" on validation
  - Don't interrupt current screen reader speech

- [ ] **Subtask 3.2**: Status updates
  - Build progress announced periodically
  - Save confirmation announced
  - File open/close announced

---

### **Task 4**: Editor Content Accessibility

Make code content accessible to screen readers.

- [ ] **Subtask 4.1**: Monaco accessibility
  - Enable Monaco's built-in screen reader mode
  - Configure accessible description of code lines
  - Announce current line on navigation

- [ ] **Subtask 4.2**: Syntax hint for screen readers
  - Optional: describe syntax structure
  - "Keyword: WHEN" instead of just "WHEN"
  - Configurable verbosity level

---

### **Task 5**: Tests

- [ ] **Subtask 5.1**: ARIA label audit
  - Automated scan for unlabeled buttons/inputs
  - All interactive elements have labels
  - Labels are descriptive and unique

- [ ] **Subtask 5.2**: Screen reader testing
  - Test with Narrator (Windows) and VoiceOver (macOS)
  - Navigate file tree → states announced correctly
  - New errors announced
  - Code content readable

---

## Dev Notes

### Monaco Accessibility Configuration

```typescript
monaco.editor.create(element, {
  accessibilitySupport: 'on',
  ariaLabel: 'JPE Code Editor',
});
```

### ARIA Live Region Pattern

```tsx
<div aria-live="polite" aria-atomic="true" className="sr-only">
  {announcement}
</div>
```
