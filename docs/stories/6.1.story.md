# Story 6.1: Secure Multi-Model AI Service Integration

## Story

**As a** Modder who wants AI assistance,
**I want** to securely connect to different AI providers (OpenAI, Claude, Qwen) with encrypted credentials,
**so that** I can use my preferred LLM for modding help without exposing my API keys.

---

## Acceptance Criteria

1. **Encrypted Credential Storage** — API keys encrypted and stored locally via CredentialManager
2. **Provider-Agnostic API** — Single interface works with OpenAI, Claude, and Qwen
3. **BaseAIService Layer** — Abstract base class for provider implementations
4. **Secure Transmission** — All API calls over HTTPS with proper error handling
5. **Tests** — Unit tests for credential encryption; integration tests with mock AI providers

---

## Tasks / Subtasks

### **Task 1**: Credential Manager

Create secure local credential storage.

- [ ] **Subtask 1.1**: Create `CredentialManager` service
  - Encrypt API keys before storage (AES-256-GCM)
  - Store encrypted keys in Electron secure storage
  - Retrieve and decrypt on demand
  - Never expose keys in logs or error messages

- [ ] **Subtask 1.2**: Key rotation and revocation
  - Support updating stored keys
  - Clear keys on user request
  - Validate key format before saving

---

### **Task 2**: AI Service Abstraction

Create the provider-agnostic AI service layer.

- [ ] **Subtask 2.1**: Create `BaseAIService` abstract class
  - Define common interface: `complete(prompt, options)`
  - Handle request formatting, response parsing
  - Error handling and retry logic
  - Rate limiting and quota tracking

- [ ] **Subtask 2.2**: Provider implementations
  - `OpenAIService`: GPT-4/GPT-3.5 integration
  - `ClaudeService`: Claude API integration
  - `QwenService`: Qwen API integration
  - Each handles provider-specific auth and formatting

---

### **Task 3**: Configuration UI

- [ ] **Subtask 3.1**: AI settings panel
  - Input fields for each provider's API key
  - "Test Connection" button validates key
  - Select default provider
  - Configure model (GPT-4, Claude Sonnet, etc.)

- [ ] **Subtask 3.2**: Usage dashboard
  - Show API usage/costs
  - Rate limit status

---

### **Task 4**: Tests

- [ ] **Subtask 4.1**: Unit tests for CredentialManager
  - Encrypt → decrypt returns original
  - Key never exposed in plaintext in storage
  - Invalid key format rejected

- [ ] **Subtask 4.2**: Unit tests for AI services

## Dev Notes

### Encryption Strategy

Use Electron's `safeStorage` API for key encryption, which uses OS-level keychain/credential manager. Fallback to app-level AES encryption with a derived key.

### Provider API Differences

| Provider | Auth | Endpoint | Model Param |
|----------|------|----------|-------------|
| OpenAI | Bearer token | api.openai.com/v1/chat/completions | model |
| Claude | x-api-key header | api.anthropic.com/v1/messages | model |
| Qwen | Bearer token | dashscope.aliyuncs.com/api/v1/services/aigc/text-generation/generation | model |
