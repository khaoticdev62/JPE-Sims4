# Story 6.3: AI-Powered Conflict & Semantic Error Detection

## Story

**As a** Modder working with multiple mod files,
**I want** AI to analyze relationships between tuning IDs and find logical conflicts,
**so that** I can catch subtle mod incompatibilities that standard validators miss.

---

## Acceptance Criteria

1. **Cross-File Analysis** — AI examines relationships between tuning IDs across all project files
2. **Logical Conflict Detection** — Overlaps, missing dependencies, and contradictory logic identified
3. **Diagnostic Panel Integration** — Conflicts reported as "Logical Warnings" in diagnostics
4. **Explanation Included** — Each warning includes plain-English explanation of the conflict
5. **Tests** — Unit tests for conflict analyzer; integration test with known conflicting mods

---

## Tasks / Subtasks

### **Task 1**: AI Conflict Analyzer

Create the analysis service for cross-file conflict detection.

- [ ] **Subtask 1.1**: Create `AIConflictAnalyzer` service
  - Collect all tuning IDs and references from project
  - Build dependency graph of mod elements
  - Send graph to AI for analysis

- [ ] **Subtask 1.2**: Conflict types
  - **ID Collision**: Two elements using same tuning ID
  - **Missing Dependency**: Reference to undefined element
  - **Contradictory Logic**: WHEN X DO Y vs WHEN X DO NOT Y
  - **Circular Reference**: A references B references A

---

### **Task 2**: AI Prompt for Conflict Detection

Design prompts for logical conflict identification.

- [ ] **Subtask 2.1**: Conflict detection prompt
  - Include full project context (tuning IDs, references, conditions)
  - Ask AI to identify potential conflicts
  - Request explanation for each finding
  - Request severity assessment

- [ ] **Subtask 2.2**: Response parsing
  - Extract structured conflict list from AI response
  - Parse: conflict type, files involved, explanation, severity
  - Validate against known conflicts

## Dev Notes

### Dependency Graph Structure

```typescript
interface DependencyGraph {
  nodes: TuningNode[]; // Each tuning ID with metadata
  edges: DependencyEdge[]; // References between nodes
}

interface TuningNode {
  id: string;
  type: 'interaction' | 'buff' | 'trait' | 'condition';
  filePath: string;
  conditions: string[]; // WHEN/ONLY_IF conditions
  actions: string[]; // DO actions
}

interface DependencyEdge {
  from: string; // Tuning ID
  to: string; // Referenced ID
  type: 'references' | 'requires' | 'conflicts';
}
```
