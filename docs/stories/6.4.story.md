# Story 6.4: Automated "Explain & Fix" Diagnostic Action

## Story

**As a** Modder encountering errors,
**I want** AI to explain why my code is invalid in plain English and propose corrections,
**so that** I can learn from mistakes while fixing them efficiently.

---

## Acceptance Criteria

1. **Plain-English Explanations** — AI explains why code is invalid in understandable terms
2. **Proposed Diffs** — AI suggests specific code corrections with diff preview
3. **One-Click Apply** — "Apply Fix" button refactors source immediately
4. **Learning Mode** — Explanation teaches concept, not just provides fix
5. **Tests** — Unit tests for explanation generator; integration test for fix application

---

## Tasks / Subtasks

### **Task 1**: Explanation Generator

Create the AI service for error explanation.

- [ ] **Subtask 1.1**: Create `AIExplanationGenerator` service
  - Accept error context: error type, code snippet, surrounding context
  - Generate plain-English explanation of why code is invalid
  - Include learning context (what concept is involved)

- [ ] **Subtask 1.2**: Explanation formatting
  - Structure: "What's wrong", "Why it matters", "How to fix"
  - Include relevant JPE syntax reference
  - Keep explanations concise (2-3 sentences)

---

### **Task 2**: Fix Proposal

Generate and present the proposed correction.

- [ ] **Subtask 2.1**: Create `AIFixProposal` service
  - Generate corrected code using AI
  - Create diff (before → after) for user review
  - Validate corrected code passes syntax check

- [ ] **Subtask 2.2**: Diff preview UI
  - Inline diff viewer (red deletions, green additions)
  - Side-by-side comparison option
  - "Apply Fix" and "Try Different Fix" buttons

---

### **Task 3**: Editor Integration

- [ ] **Subtask 3.1**: AI Fix button in diagnostics
  - Each diagnostic item has "AI Fix" button
  - Click → loading state while AI analyzes
  - Result: explanation + diff preview

- [ ] **Subtask 3.2**: Fix application
  - "Apply Fix" replaces code with corrected version
  - Recorded as undoable transaction
  - Re-validation triggered automatically
  - Toast: "Fix applied. Ctrl+Z to undo"

---

### **Task 4**: Tests

- [ ] **Subtask 4.1**: Unit tests for AIExplanationGenerator
  - Explanation generated for each error type
  - Explanation includes learning context
  - Response parsing correct

- [ ] **Subtask 4.2**: Unit tests for AIFixProposal
  - Fix proposed for correctable errors
  - Fixed code passes validation
  - Diff accurately represents changes

- [ ] **Subtask 4.3**: Integration test
  - Error in diagnostics → AI Fix clicked
  - Explanation shown with diff preview
  - Fix applied → error resolved

## Dev Notes

### Explanation Prompt Template

```
A JPE modder has the following error. Explain what's wrong and why.

Error: {errorType}
Code: {codeSnippet}
Context: {surroundingCode}

Explain in 2-3 sentences:
1. What's wrong with this code
2. Why it matters (what game issue it would cause)
3. How to fix it (general approach, not specific code)

Keep the explanation in plain English suitable for beginners.
```

### Fix Prompt Template

```
Generate corrected JPE code for the following error.

Error: {errorType}
Current Code: {codeSnippet}

Return ONLY the corrected JPE code, no explanation.
```
