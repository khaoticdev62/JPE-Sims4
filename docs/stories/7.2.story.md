# Story 7.2: One-Click Mod Update & Manifest Patching

## Story

**As a** Modder maintaining a mod portfolio,
**I want** to update mod versions and patch manifests with a single click,
**so that** I can keep my mods current without manual binary rebuilding.

---

## Acceptance Criteria

1. **Version Increment** — "Update Version" action increments version in internal manifest resource
2. **Binary Integrity** — Package reconstructed with 100% binary integrity using PackageStreamWriter
3. **Direct Save** — Result saved directly back to Mods folder for immediate game testing
4. **Update History** — Version change history tracked and viewable
5. **Tests** — Unit tests for manifest patcher; integration test with real .package files

---

## Tasks / Subtasks

### **Task 1**: Manifest Reader/Writer

Create the manifest parsing and patching service.

- [ ] **Subtask 1.1**: Create `ManifestPatcher` class
  - Read version manifest from .package resource
  - Parse version number (major.minor.patch)
  - Increment version (auto or manual: major/minor/patch)
  - Write updated manifest back to package

- [ ] **Subtask 1.2**: PackageStreamWriter integration
  - Reconstruct .package with updated manifest
  - Ensure 100% binary integrity (no corruption)
  - Preserve all other resources unchanged

---

### **Task 2**: Version Management UI

- [ ] **Subtask 2.1**: Create `VersionManager` component
  - Display current version number
  - Version increment buttons: +Major, +Minor, +Patch
  - Custom version input field
  - Update history list with timestamps

- [ ] **Subtask 2.2**: One-click update
  - "Update & Save" button
  - Progress indicator during patching
  - Success toast: "Version bumped to X.Y.Z and saved"
  - Error handling for write failures

---

### **Task 3**: Update Pipeline

- [ ] **Subtask 3.1**: Create `ModUpdateService`
  - Read current .package
  - Patch manifest resource
  - Reconstruct package
  - Write to Mods folder (with backup)

- [ ] **Subtask 3.2**: Backup before update
  - Create .backup copy before modifying
  - Rollback option if update fails
  - Confirm before overwrite

---

### **Task 4**: Tests

- [ ] **Subtask 4.1**: Unit tests for ManifestPatcher
  - Version incremented correctly
  - Invalid version format rejected
  - Manifest parsed from package correctly

- [ ] **Subtask 4.2**: Unit tests for ModUpdateService
  - Package reconstructed with integrity
  - Backup created before update
  - Write to Mods folder succeeds

- [ ] **Subtask 4.3**: Integration test
  - Open .package → update version → save

## Dev Notes

### Version Format

Semantic versioning: `major.minor.patch`
- **Major**: Breaking changes
- **Minor**: New features (backwards compatible)
- **Patch**: Bug fixes

### Manifest Resource Location

In Sims 4 .package files, manifest is typically a specific resource type with known type/group/instance IDs.
