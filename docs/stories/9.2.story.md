# Story 9.2: Passive Engine Monitoring

## Story

**As a** Modder playing Sims 4 with JPE-Live active,
**I want** to see real-time tuning execution logs from the game engine,
**so that** I can debug my mod interactions as they happen.

---

## Acceptance Criteria

1. **Event Capture** — JPE Studio captures tuning execution events from bridge script
2. **<5% CPU Impact** — Data ingestion consumes negligible CPU during gameplay
3. **60 FPS UI** — Application UI remains responsive during heavy log bursts
4. **Live Log Viewer** — Real-time log display with filtering
5. **Tests** — Unit tests for event processor; load test for log burst handling

---

## Tasks / Subtasks

### **Task 1**: Event Receiver

Create the server that receives events from the bridge.

- [ ] **Subtask 1.1**: Create `BridgeEventReceiver`
  - Start local socket server on configured port
  - Accept connections from bridge script
  - Parse incoming event messages
  - Handle disconnects and reconnections

- [ ] **Subtask 1.2**: Event types
  - `tuning_execute`: Tuning block executed
  - `error`: Exception in tuning
  - `state_change`: Game state changed
  - `heartbeat`: Bridge alive check

---

### **Task 2**: Event Processor

Process and store incoming events efficiently.

- [ ] **Subtask 2.1**: Create `TuningEventProcessor`
  - Receive parsed events from receiver
  - Map tuning IDs to known mod elements
  - Store in ring buffer (last N events)
  - Notify subscribers of new events

- [ ] **Subtask 2.2**: Performance optimization
  - Event processing on background thread
  - Batch UI updates (don't update per-event)
  - Ring buffer prevents memory growth

### **Task 3**: Live Log Viewer UI

Create the real-time log display.

- [ ] **Subtask 3.1**: Create `LiveLogViewer` component

  - Color-coded by event type (execute=teal, error=red)
  - Timestamp on each event
  - Tuning ID clickable (jumps to source file)

- [ ] **Subtask 3.2**: Filtering
  - Filter by event type
  - Filter by mod/project
  - Search by tuning ID
  - Pause/resume auto-scroll

- [ ] **Subtask 3.3**: Performance

  - Throttle rendering during bursts

## Dev Notes

### Ring Buffer

Fixed-size circular buffer for events:
```typescript
class RingBuffer<T> {
  private buffer: T[];
  private head: number = 0;
  private count: number = 0;

  push(item: T): void {
    this.buffer[this.head] = item;
    this.head = (this.head + 1) % this.buffer.length;
    if (this.count < this.buffer.length) this.count++;
  }
}
```
